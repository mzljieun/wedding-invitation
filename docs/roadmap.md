# 작업 순서와 결정 기록

| 단계 | 작업 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 0 | 기존 개발 초안 정리와 설계 재구성 | 준비 페이지 기준 복원, 예식 정보·요구사항 보존 | 완료 |
| 1 | npm 기반 React + Vite 기본 설정 | 설치, 개발 서버, 프로덕션 빌드 확인 | 완료 |
| 2 | 준비 페이지 React 전환 | 기존 문구와 디자인을 좁은 브라우저 화면에서 비교 | 완료 |
| 3 | 청첩장 화면을 영역별 구현 | 표지부터 한 영역씩 구현·검증 | 진행 중: 표지·초대 문구 완료 |
| 4 | 미리보기와 공개 배포 | 미리보기 검증 후 기존 주소에 공개, 준비 화면 복귀 방법 확인 | 예정 |

- **npm 선택:** 이전 pnpm 사용은 작업 환경에 내장되어 있었기 때문입니다. 이 프로젝트는 npm으로 충분하며, 사용자가 익히고 쓰려는 도구로 통일합니다. 설치 후 `package-lock.json`을 관리합니다.
- **새 출발:** 이전 React 전환 초안은 작업 폴더에서 제거합니다. 예식 정보와 기능 요구사항은 문서로 보존합니다.
- **테스트 배포:** 별도 미리보기 주소를 우선 검토합니다. 실제 서비스와 접근 범위는 배포 단계에서 결정합니다.

검증 기록:

- 0단계: 화면 파일을 main의 준비 페이지와 비교했습니다.
- 1단계: npm으로 의존성을 설치하고 `package-lock.json`을 생성했습니다. `npm run build`로 `dist/`를 생성했고, Vite 개발 서버의 `/wedding-invitation/` 응답에서 준비 페이지 문구를 확인했습니다. 이 단계에서는 기존 HTML·CSS를 유지했으므로 React 화면의 브라우저 비교는 2단계에서 진행합니다.
- 2단계: 준비 화면을 `src/ComingSoon.jsx`로 옮기고, `src/main.jsx`에서 React로 렌더링합니다. 기존 CSS를 유지했습니다. 빌드 후 `/wedding-invitation/`에서 제목과 문구를 확인했고, 같은 브라우저 창 크기에서 전환 전후 캡처가 일치했습니다. 실제 모바일 기기와 공개 배포는 검증 범위에 포함하지 않았습니다.
- 3-1단계(표지): `src/Cover.jsx`와 전용 CSS에 흑백 가로 사진, 이름, 예식 일시와 장소를 배치했습니다. 원본은 보존하고 긴 변 1,800px의 EXIF 없는 복사본을 사용합니다. 로컬 브라우저에서 기본 준비 화면과 좁은 창의 표지 미리보기를 확인했습니다. 배포용 빌드가 통과했고 표지 사진이 결과물에 포함되지 않았습니다. 실제 휴대폰과 공개 배포는 확인하지 않았습니다. 다음 범위는 초대 문구입니다.
- 3-2단계(초대 문구): `src/Invitation.jsx`와 전용 CSS에 인사말 초안과 두 사람의 서명을 추가했습니다. `WeddingPreview.jsx`에서 표지 아래에 연결했고, 좁은 브라우저 창에서 문구와 배치를 확인했습니다. 배포용 빌드는 통과했으며 미리보기는 포함되지 않습니다. 문구 확정, 달력, 오시는 길은 이번 범위에 포함하지 않았습니다. 다음 범위는 예식 일정입니다.
